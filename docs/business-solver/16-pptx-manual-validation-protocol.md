# 16: PowerPoint & Keynote Manual Validation Protocol

> Status: **ready to run (2026-11-21); not yet executed.** Microsoft PowerPoint and Apple Keynote are not available in the build environment, so these checks need a person on real machines.
> Purpose: confirm that exported decks are **genuinely editable** and **correct in Arabic and English** in the apps customers use. Document rendering differences, connector behaviour, Arabic typography and editability.
> Test files: `phase0/results/validation-pack/validation-pack-ar.pptx` and `validation-pack-en.pptx` (10 slides each, built by `phase0/experiments/e-pptx/build_validation_pack.py` from the same code paths as product exports). Each test slide shows its test ID (T01–T08) in the top corner, and **its speaker notes contain the exact steps and the expected result.**

## 4. How to record results: consolidated workbook

Use **`phase0/results/validation-pack/PowerPoint-Manual-Test-Results.xlsx`** (generated by `experiments/e-pptx/make_results_template.py`). It has five sheets:

| Sheet | Content |
|---|---|
| **Instructions** | Steps, definitions, severity scale (English + Arabic) |
| **Setup** | One row per run: R1 PowerPoint Win AR (fonts installed) · R2 PowerPoint Win EN · R3 PowerPoint Win AR (fonts **not** installed) · R4 PowerPoint Mac AR · R5 PowerPoint Mac EN · R6 Keynote AR · R7 Keynote EN. Records app build, OS, tester, date, *opened without repair prompt (Y/N)*, font substitution |
| **Results** | 56 rows (7 runs × T01–T08). **Six dimensions** per row, each PASS / PARTIAL / FAIL (dropdown), grey = not applicable: **Visual rendering · Arabic typography · Text direction · Shape editability · Connector behaviour · Layout consistency**. Plus *Overall* (automatic), *Severity (worst)*, notes, screenshot file name |
| **Differences** | Cross-app log: one row per observed difference, with what PowerPoint Windows, PowerPoint Mac and Keynote each did, impact, screenshots, follow-up issue |
| **Summary** | Exit criteria from §6, computed automatically; ends with **EXIT CRITERIA MET: YES/NO** |

Dimension definitions (also in the workbook):
- **Visual rendering:** looks as in the reference render; nothing missing or clipped.
- **Arabic typography:** letters joined and shaped; diacritics placed correctly; digits correct in both systems; no unexpected font substitution.
- **Text direction:** RTL paragraphs; mixed Arabic/Latin order; tables mirrored except the heat matrix (by design); Gantt time right-to-left in Arabic.
- **Shape editability:** text, cells and shapes edit, move and resize as native objects; typing keeps direction and font.
- **Connector behaviour:** connectors stay attached and re-route when shapes move; undo restores them.
- **Layout consistency:** positions, line breaks and sizes match the reference; no overflow or unexpected autofit shrink.

Severity for PARTIAL/FAIL: critical (file unusable or meaning wrong) · high (editability or RTL broken) · medium (visible defect) · low (cosmetic). Save screenshots as `screens/<Run>-<Test>.png`. Never include customer data; the packs contain only synthetic content.

Verification of the workbook itself (2026-11-21, on synthetic copies only): a blank workbook reports exit criteria **NO**; an all-PASS copy reports **YES**; a copy with one Keynote "high" finding reports **NO** and counts the finding. The generator refuses to overwrite an existing workbook.

## 5. What the write-up must cover (appended to doc 13 as an update)

1. **Rendering differences** between PowerPoint Windows, PowerPoint Mac and Keynote (fonts, line breaks, table borders, connector paths, colours).
2. **Connector behaviour:** attached or detached after moves, after undo, after copy-paste between slides, and after a round trip through Keynote.
3. **Arabic typography:** shaping, diacritics, digit systems, mixed-direction order, line spacing, font substitution in condition B.
4. **Editability:** text, tables, shapes and connectors editable with expected behaviour; no unexpected autofit shrink.
5. A pass/fail summary against doc 12 §E.2.

## 6. Exit criteria (from doc 12 §E.2)

All of the following, in PowerPoint Windows **and** Mac (Keynote: no critical or high findings):
- 100% of decks open without repair.
- T01–T06 PASS in both languages.
- T07 and T08: every connector stays attached after moves and undo.
- No critical or high typography finding in condition A. Condition B findings are documented, with a mitigation (e.g. the "system font" export mode).

Any failure becomes an export-service issue (doc 15) with the screenshot and the test ID.
